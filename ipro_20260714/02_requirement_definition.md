# **「TaskRescue（タスク・レスキュー）」 要件定義書**

## **1\. システム概要**

* **目的・コンセプト：**  
  「メンバーがどこで詰まっているか」が一目でわかり、その場ですぐに助け合える、スレッドチャット機能付きの超軽量タスク管理ツール。少人数チームにおける「孤立」を防ぎ、気軽にヘルプを出して相互扶助（助け合い）を促進することを目的とする。  
* **動作環境：**  
  * XAMPP / MAMP 環境  
  * URL: http://localhost:8080/task\_rescue/  
  * データベース名: task\_rescue\_db  
  * データベース接続情報: ユーザー名 root / パスワード root

## **2\. 機能要件（今回実装する対象）**

これまでのブレストに基づき、以下の機能を段階的に実装します。

### **① ユーザー管理機能**

* \[ \] **新規ユーザー登録機能（難易度：レベル3 \- 実務標準）**  
  * ユーザー名、パスワードを入力して新しいアカウントを作成できる。  
* \[ \] **ログイン・ログアウト機能（難易度：レベル3 \- 実務標準）**  
  * 登録した情報でログインし、セッション（Session）を維持できる。ログアウトでセッションを破棄する。

### **② 一覧リスト型ステータスダッシュボード**

* \[ \] **タスク一覧表示機能（難易度：レベル2 \- 基本）**  
  * メンバー全員のタスクと現在のステータスが縦一列に並ぶシンプルな画面。  
* \[ \] **ステータス切り替え機能（難易度：レベル4 \- 応用）**  
  * 自分の状態を「着手中」「ヘルプ（詰まり中）」「完了」に切り替えられる。  
  * **【非同期通信 (Fetch API) 実装】**：ボタンをクリックした際、画面全体をリロードすることなく、非同期通信でデータベースのステータスを更新し、画面上の表示を即座に書き換える。

### **③ ヘルプ登録・編集機能**

* \[ \] **ダッシュボード内ポップアップ入力機能（難易度：レベル2〜3 \- 基本〜実務標準UI）**  
  * ステータスを「ヘルプ（詰まり中）」に変更する際、ダッシュボード上にモーダル（ポップアップ）が表示され、「タスク名」と「ヘルプ詳細（エラー内容など）」を入力・編集して登録できる。

### **④ ヘルプ特化型スレッドチャット機能**

* \[ \] **別タブ型チャット機能（難易度：レベル2 \- 基本）**  
  * 「ヘルプ」状態になっているタスクをクリックすると、別タブでそのタスク専用の「チャット詳細ページ」が開く。  
  * そのタスクに紐づくコメント一覧を表示し、アドバイスを新規投稿できる。

### **⑤ 解決後の「ありがとう！」演出（スタンプリアクション）機能**

* \[ \] **簡易リアクション機能（難易度：レベル2 \- 基本）**  
  * チャット詳細ページ内の各コメント（アドバイス）に対し、Teamsのリアクションのように、絵文字スタンプをクリックして手軽に「ありがとう」のリアクションを送ることができる。  
  * **【画面リロード型で実装】**：スタンプをクリックすると画面リロードを伴い、スタンプ数がカウントアップされるシンプルな仕様で確実に実装する。

## **3\. 非機能要件・セキュリティ要件（★意識強化項目）**

安全かつ安定した運用のために、以下の実装方針を徹底します。

* **セキュリティ要件詳細：**  
  * **① 入力値検証（バリデーション）方針**  
    * 空欄での送信防止、文字数制限（データベースの桁あふれ防止）をサーバーサイド（PHP）とクライアントサイド（HTMLの required 等）の両方で行う。  
  * **② 表示時のサニタイズ（エスケープ）方針**  
    * ユーザーから投稿された文字をブラウザに描画する際は、必ず htmlspecialchars() を用いてXSS（クロスサイトスクリプティング）を防止する。  
  * **③ データベースセキュリティ（PDO適用）方針**  
    * データベース操作にはPDOを使用し、SQL文の実行時はプリペアドステートメント（prepare と execute）を用いて SQLインジェクションを完全に防ぐ。  
  * **④ 認証とパスワード保護方針**  
    * パスワードはプレーンテキストではなく、必ず password\_hash() 関数を使ってハッシュ化した上でデータベースに保存する。  
* **エラーハンドリング方針：**  
  * データベース接続エラーや実行エラーが発生した際、生のSQLエラー（DB構造やパス情報など）を画面に表示せず、セキュリティに配慮した汎用メッセージ（例：「システムエラーが発生しました。時間をおいてやり直してください」）を画面に表示させる。

## **4\. 今回スコープアウト（削除）した機能**

技術的難易度や開発期間を考慮し、初期設計からあえて除外した機能です。

* **簡易リアクション機能の非同期通信（Fetch API）化（レベル4：応用）**  
  * *判断理由:* ステータス切り替え機能の非同期通信化（レベル4）に開発リソースを集中させるため。リアクション機能は確実かつシンプルな「画面リロード型（レベル2）」に留めることで、期間内の完成率を高めます。  
* **最初からの完全なリアルタイム処理（レベル5：実務発展）**  
  * *判断理由:* WebSocketなどのリアルタイム双方向通信は、学習コストおよび開発期間が非常に大きいため、今回はスコープ外とします。
