# **「TaskRescue（タスク・レスキュー）」機能検討 要望書**

## **1\. アプリケーションの概要・コンセプト**

**「メンバーがどこで詰まっているか」が一目でわかり、その場ですぐに助け合える、スレッドチャット機能付きの超軽量タスク管理ツールです。**

既存の有料ツールや複雑なプロジェクト管理ツールとは異なり、直感的なステータス切り替えと課題解決に特化したチャット機能を通じて、少人数チーム開発における「孤立」を防ぎ、相互扶助（助け合い）を促進するためにこのアイデアを選択しました。

## **2\. 解決する課題とターゲットユーザー**

* **対象ユーザー：** 大学や専門学校の実習などでチーム開発を行っている、少人数の学生開発チーム  
* **解決するペインポイント：**  
  * 既存の管理ツールは多機能すぎて更新が形骸化しやすい  
  * チャットツール（LINEやDiscordなど）だけでは、誰が今何の作業をしていて、どこで詰まっている（悩んでいる）のかを聞かないとわからない  
  * 「今さらこんなことを聞いてもいいのだろうか…」という心理的ハードルがあり、困っているメンバーが自発的に相談しづらい  
* **提供する独自の価値（ベネフィット）：**  
  * 一覧リスト型の超シンプルな画面構成により、メンバー全員の状況（着手中・詰まり中・完了）を1秒でスキャン可能  
  * 「ヘルプ（詰まり中）」ステータスを選択すると、困っているタスク名と具体的なエラー内容が強調表示され、メンバー全員から見えるようになる  
  * そのタスクに対して専用のスレッドチャットが自動生成されるため、「何についての会話か」がブレずにその場でスムーズにアドバイスを送ることができる

## **3\. 動作・作業環境（必ず半角英数字のみ）**

* **ドキュメントルート（フォルダ名）：** /task\_rescue/  
* **データベース名（仮）：** task\_rescue\_db

## **4\. 実装機能一覧**

### **① 必須機能（コアとなる面白い体験や最低限必要な機能）**

* \[ \] **ユーザー管理機能**  
  * チームメンバーの新規登録、ログイン・ログアウト処理。  
* \[ \] **一覧リスト型ステータスダッシュボード**  
  * メンバー全員のタスクと現在の状況が上から縦一列に並ぶシンプルな画面。  
  * 自分の状態を「着手中」「ヘルプ（詰まり中）」「完了」のいずれかに1クリックで切り替え可能にする。  
* \[ \] **ヘルプ登録・編集機能**  
  * 「ヘルプ」ステータスにする際、現在取り組んでいる「タスク名」と、具体的に何に困っているか（エラー内容など）の「ヘルプ詳細」を入力して登録できる。  
* \[ \] **ヘルプ特化型スレッドチャット機能**  
  * 「ヘルプ」状態になっている各タスクに対し、個別のアドバイス用チャット（スレッド）が開き、コメントを投稿・閲覧できる。

### **② 付加価値・トレンド機能（さらに面白く・使いやすくするための機能）**

* \[ \] **解決後の「ありがとう！」演出機能**  
  * ヘルプから「完了」に変更する際、チャットでアドバイスをくれたメンバーに対して「感謝の気持ち」を送信（または自動サンクスログの生成）し、お互いのモチベーションを向上させる仕組み。

### **③ 実務・セキュリティ要件（安全な運用のための必須要件）**

* \[ \] **パスワード暗号化**  
  * password\_hash 関数による安全なパスワードのハッシュ化およびDB保存。  
* \[ \] **脆弱性対策**  
  * プリペアドステートメントを用いたSQLインジェクション対策。  
  * htmlspecialchars 関数によるXSS（クロスサイトスクリプティング）対策。  
  * セッションとトークンを用いたCSRF（クロスサイトリクエストフォージェリ）対策。

## **5\. 次のステップ（要件定義に向けた懸念点やアドバイス）**

* **シニアエンジニアからのシステム設計アドバイス：**  
  * **テーブル設計のコツ：** users（ユーザーテーブル）、tasks（タスク・ステータステーブル）、chats（チャット履歴テーブル）の3つを用意しましょう。chats には、どのタスクに対する書き込みかが分かるように外部キー（task\_id など）を必ず持たせる設計にします。  
  * **レベル4（Ajax非同期通信）へのステップアップ案：** 最初は画面をリロードする通常のフォーム送信で構築し、動くものが完成した後に「チャットの送信」や「ステータスの切り替え」を Fetch API などを用いた非同期処理に書き換えていくと、ページ遷移がなくなり「パッと見でわかる」アプリの良さがさらに引き立ちます。まずは基本（レベル3）をしっかりと固めていきましょう。
